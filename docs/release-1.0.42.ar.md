# فصل حركة الشريط عن تخطيط البطاقات — 1.0.42

أبلغ المستخدم أن البطاقات تقفز عند ارتفاع أدوات السوق رغم تهدئة السرعة. أثبت فحص التنفيذ أن الأدوات كانت تغيّر ارتفاعها الأصلي في كل إطار، مع بقاء ارتفاع مقدمة القائمة ثابتًا. الاختبارات السابقة كانت تقيس ثبات القائمة فقط، ولم تشترط ثبات ارتفاع الشريط نفسه أو مساواة حركة البطاقة لحركة التمرير.

أصبحت الأدوات كتلة ثابتة القياس تتحرك كاملة بالـtransform داخل حاوية ثابتة ومقصوصة. لم تعد عملية الطي تصغّر ارتفاع الأدوات أو تعيد ترتيب التصنيفات في كل إطار. تغطي حافة علوية ثابتة بقايا الجزء المخفي، ويظل الغلاف المفرغ يمرر اللمس إلى بطاقات الإعلانات. تبقى الخلفية معتمة حول الحواف في النمطين.

قرب أول بطاقة يُحصر الموضع المرئي للشريط بإزاحة القائمة دون إعادة ضبط قيمة الحركة وإلغائها في كل حدث. يبدأ البحث والسحب اليدوي وإعادة ضبط التصنيف من الموضع المرئي الحالي، فلا يُكشف موضع حركة قديم عند تغيير ملكية التحكم. يقرأ أسلوب الحركة مدخلاته المشتركة مباشرةً ليُحدَّث في دورة المراقبة نفسها، دون تأخير قيمة مشتقة إضافية.

يبقى تعويض موضع أول بطاقة محصورًا بالسحب اليدوي الصريح للشريط وبإعادة ضبط نتائج البحث والتصنيفات. أثناء تمرير البطاقات والقصور الذاتي لا يصدر الشريط أوامر تمرير للقائمة. لا تُترجم قائمة البطاقات ككتلة، ولا يوجد تحويل إزاحة عند تسليم التحكم يمكن أن يؤخر استجابة السحب.

أصبحت اختبارات الحركة تشترط ثبات الارتفاع الأصلي للشريط والأدوات، وثبات أبعاد القائمة، وعدم صدور أوامر تمرير أثناء تحريك البطاقات، ومساواة إزاحة البطاقة على الشاشة لعكس إزاحة التمرير. فشل التنفيذ السابق في شرط ثبات ارتفاع الشريط. الاختبارات التنفيذية تغطي أيضًا الحركة بالـtransform وحده وبدء فتح البحث من موضع ظاهر قرب أول بطاقة.

نجح فحص TypeScript وESLint، و155 اختبارًا، و28 حالة حركة (14 باللمس و14 بالماوس)، و8 حالات تصفح معزولة دون أخطاء متصفح. أظهر اختبار اللمس صفر إزاحة إضافية للبطاقات وصفر أوامر تمرير منافسة عبر 348 إطارًا لحالات متابعة البطاقات. نجح تصدير Android وiOS والويب. كشف الاختبار السلبي 98 بكسلًا عند إزالة طبقتَي تغطية الحواف، وأظهرت حالات التغطية الفعلية صفر تسرب.

لم تتغير مسارات API أو التصنيفات أو التحميل المتتابع. لا تمثل اختبارات React Native Web قياسًا لمعدل الإطارات الأصلي على الهاتف؛ لم يكن جهاز متصلًا أو محاكي Android مثبتًا أثناء الإصلاح. يلزم تثبيت البناء الجديد للتحقق النهائي على الجهاز.

رقم الإصدار `1.0.42`، ويظل رمز البناء متزايدًا حسب إعداد Codemagic الحالي.
