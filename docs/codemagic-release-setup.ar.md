# إعداد بناء سوق حمد على Codemagic

يبدأ مسار Android عند دفع التغييرات إلى الفرع `main` وينتج AAB. مسار **Souq Hamad iOS Release** يبدأ يدويًا من Codemagic وينتج IPA بعد إعداد التوقيع، دون رفع تلقائي إلى App Store Connect أو طلب مراجعة. رقم الإصدار المضبوط حاليًا هو `1.0.57`، ومعرّف التطبيق الإنتاجي هو `com.souqhamad.app` على المنصتين. رقم البناء الأساسي `433`، وأثناء Codemagic يساوي `433 + PROJECT_BUILD_NUMBER`. يستمر العداد العام للمشروع من الإصدار السابق `1.0.54` ليكون رمز البناء الجديد أعلى منه؛ لا يُعاد ضبطه عند تغيير اسم الإصدار. رُفعت القاعدة بعد تأكيد رمز Google Play `432` للإصدار `1.0.57`؛ أصغر رمز في Codemagic الآن `434` حتى عند بدء عدّاد مشروع جديد من `1`. عند إعادة إنشاء المشروع أو عداده، راجع أعلى رمز مستخدم في المتجر قبل تحديد القاعدة.

خطوة **Verify store build number** تشترط `CM_BUILD_ID` وعدادًا صالحًا وتعرض الإصدار ورمز البناء في السجل. بعد `expo prebuild` يتحقق مسار Android من تطابق `versionCode` و`versionName` في المشروع المولّد مع هذه القيم، ويتوقف عند اختلافها. بعد اكتمال البناء، نزّل ملف AAB من ذلك البناء الجديد وارفعه إلى Google Play؛ الملف الذي نُزّل سابقًا يبقى محتفظًا برمزه القديم.

## إعداد Codemagic مرة واحدة

يستخدم المساران Node `22.23.3` المتوافق مع Expo 58، ويجريان `verify-node` قبل تثبيت الاعتماديات. لا تستخدم Node `22.11.0` لهذا الإصدار من Expo. بيئة GitHub التي تختار Node 24 من `.nvmrc` مدعومة أيضًا عند `24.3` أو أحدث ضمن هذا الخط.

1. أضف مستودع `mahersss024-oss/app` إلى حساب Codemagic، واختر ملف `codemagic.yaml` من الفرع `main`.
2. فعّل Webhook الخاص بـ GitHub لأحداث الدفع. ملف YAML يراقب `main`، لكن الدفع وحده لا يبدأ البناء ما لم يكن المشروع متصلًا وWebhook مفعّلًا.
3. من **Environment variables** أنشئ مجموعة باسم `android_signing`، وأضف إليها المتغيرات التالية مع تفعيل **Secret** لكل قيمة:
   - `CM_KEYSTORE`: محتوى ملف keystore الأصلي بترميز Base64.
   - `CM_KEYSTORE_PASSWORD`: كلمة مرور ملف keystore.
   - `CM_KEY_ALIAS`: اسم المفتاح داخل الملف.
   - `CM_KEY_PASSWORD`: كلمة مرور المفتاح.

   يستخدم مسار Android هذه المجموعة مباشرة، ويفك ترميز `CM_KEYSTORE` إلى ملف مؤقت أثناء البناء. لا تضف مرجع `android_signing` ضمن Code signing identities لهذا المسار. استخدم keystore الرفع نفسه الذي وقّع الإصدار السابق؛ تغيير المفتاح قد يمنع تحديث التطبيق المنشور.
4. لآيفون، جهّز App ID مطابقًا للحزمة بقدرات **Sign in with Apple** و**Push Notifications** و**Associated Domains**. يستخدم المسار طريقة جلب ملفات التوقيع عبر App Store Connect API؛ أنشئ مجموعة متغيرات سرية باسم `ios_release` وفق [خطوات تجهيز آيفون](ios-preparation.ar.md). لا يفترض المسار وجود اتصال مسمّى في Teams ← Integrations.
5. آيفون يستخدم Apple فقط؛ لا يحتاج إعداد Google iOS أو Firebase iOS. يتحقق المسار من مفاتيح التوقيع وXcode قبل التثبيت، ثم يولّد المشروع ويثبت CocoaPods، ويجلب أو ينشئ ملفات توقيع App Store المطابقة. بعد إنشاء IPA يفحص الإصدار والهوية والصلاحيات والتوقيع. لا يعني اجتياز هذه الفحوص اكتمال إعداد AWS أو قبول مراجعة Apple.
6. يستخدم المساران `https://souqhamad.com` صراحة، ويجريان TypeScript وlint واختبارات التكامل المحلية قبل توليد المشروع الأصلي. أبقِ بيانات الدخول والتوقيع ومفاتيح APNs/FCM في خدمة البناء أو السيرفر وفق وظيفتها.

المخرجات المتوقعة هي `*.aab` من مسار Android و`*.ipa` من مسار iOS. لا يحتوي المستودع على مفاتيح توقيع أو كلمات مرور. إذا لم تُضف مجموعة المنصة أو كانت بياناتها غير صحيحة، فسيفشل المسار قبل توقيع الحزمة. مفاتيح Apple الخاصة للتوقيع تبقى في Codemagic، ومفاتيح تسجيل الدخول وAPNs تبقى في AWS.

## فحص أسماء موارد أندرويد

تنتج خطوة **Verify bundled Android resource names** حزمة Android وخريطة الصور والخطوط التي يستخدمها التطبيق فعليًا، ثم تفحص أسماء الموارد قبل Gradle. يستخدم الفحص قواعد التسمية من نسخة Expo المثبتة؛ اختلاف الامتداد وحده لا يميز موارد أندرويد. لذلك يحمل الشعار اسم `hamad-market-wordmark.webp` ومعاينته اسم `hamad-market-wordmark-fallback.png`. يبقى محتوى الصورتين كما هو. يعمل الفحص نفسه في GitHub Actions، ويتوقف مع أسماء الملفات المتعارضة عند إضافة مورد مكرر لاحقًا.

يمكن تشغيله محليًا من جذر تطبيق الجوال:

```powershell
pnpm.cmd exec expo export --platform android --dump-assetmap --output-dir .data/android-resource-check
node scripts/verify-android-assets.cjs .data/android-resource-check/assetmap.json
```

هذا الفحص لا يبني أو يوقّع AAB؛ تظل خطوة `bundleRelease` في Codemagic مطلوبة لإنتاج الحزمة.

## إشعارات أندرويد وشاشة الافتتاح

أضيفت الوحدة الأصلية `expo-blur` للنمط الزجاجي لشريط التنقل؛ يلزم بناء جديد لتضمينها. يستخدم أندرويد 12 فأعلى تمويهاً أصلياً، وتعرض الإصدارات الأقدم السطح البديل. ألوان النظام والتمييز الأصلية ضُبطت على الأخضر الهادئ للنمطين، والمظهر يدعم «حسب الجهاز / فاتح / داكن».

يستخدم إصدار الإنتاج ملف العميل `config/google-services.production.json` للحزمة `com.souqhamad.app` ومشروع Firebase `souqhamad`. هذا تعريف عميل عام؛ مفاتيح حساب الخدمة الخاصة تبقى في AWS ولا تُضمّن في التطبيق. يجب أن يطابق `FIREBASE_PROJECT_ID` في السيرفر مشروع العميل، مع بيانات `FIREBASE_CLIENT_EMAIL` و`FIREBASE_PRIVATE_KEY` الصالحة للإرسال.

تتحقق خطوة **Verify Android notification configuration** من الملف والحزمة وتمنع استخدام ملف حساب خدمة خاص. يمكن تحديد مسار ملف عميل مختلف عبر `GOOGLE_SERVICES_JSON` أو محتواه بترميز Base64 عبر `GOOGLE_SERVICES_JSON_BASE64`؛ عند استعمال Base64 يجهز السكربت ملفًا مؤقتًا ويصدر مساره إلى Codemagic. بعد `prebuild` يُفحص وجود الملف وإضافة Google Services ودعم حدث `OPEN_APP` المطابق للسيرفر.

شاشة النظام أصبحت خلفية خضراء دون تكرار الشعار؛ تنتقل إلى شاشة الترحيب المتحركة بعد تجهيز الخطوط والخلفية والشعار المحليين. شاشة الترحيب تستخدم خلفية الأيقونة الخضراء المزخرفة بكامل المساحة، والشعار الأصلي في المنتصف وشريطاً متحركاً أسفلها، وتحته عبارة «سوقك الذكي للبيع والشراء». هذه الإعدادات الأصلية تتطلب بناء AAB/IPA جديدًا؛ تحديث JavaScript وحده لا يغيّرها. يُتحقق من الافتتاح واستقبال الإشعارات وفتح وجهتها على حزمة إصدار وجهاز فعلي، وتظل أذونات الإشعارات تحت تحكم إعدادات النظام.
